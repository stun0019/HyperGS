# Acceptance Criteria

Write acceptance criteria as observable outcomes, not implementation tasks.

Each criterion must identify:

- Actor or system state
- Trigger or action
- Observable result
- Relevant boundary or failure behavior
- Verification method

Prefer compact Given/When/Then examples for behavioral rules. Include performance, accessibility, security, data, compatibility, and recovery criteria only when they materially apply.

A criterion passes only when evidence from an actual test, build, inspection, or approved review supports it. Planned tests are not passed tests.
