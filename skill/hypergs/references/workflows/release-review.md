# Release Review Workflow

## Lead and support

Lead: Producer. Support: Client Engineer, Server Engineer, Market Analyst, Data Analyst, UI/UX Designer, and Art Director as affected.

## Procedure

1. Identify the immutable release candidate, target channel, supported platforms, and user authorization boundary.
2. Verify build provenance, tests, performance, compatibility, privacy, accessibility, store assets, versioning, telemetry, support, monitoring, backups, rollback, and incident ownership.
3. Confirm release notes and known issues match the candidate.
4. Separate readiness review from the external publishing action.

## Completion

Return `ready`, `not ready`, or `blocked` with explicit evidence and owners. Publishing, production migration, and public communication require explicit authorization.
