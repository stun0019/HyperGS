# Backend Feature Workflow

## Lead and support

Lead: Server Engineer. Support: Client Engineer, Data Analyst, and Producer.

## Procedure

1. Establish whether a server is necessary and define the trust boundary.
2. When the product claims online co-op, a shared world, or an MMO, map each public claim to authoritative state, identity, persistence, synchronization, social presence, failure recovery, and measurable concurrency evidence using `genre-promise.md`.
3. Specify contracts, authorization, validation, errors, timeouts, retries, idempotency, schemas, and migrations.
4. Define local-development and production-like verification paths.
5. Implement server and client integration with contract and failure tests.
6. Review secrets, personal data, logging, rate limits, observability, backup, rollback, and operating cost.

## Completion

Provide verified contracts, failure behavior, and honest product-label implications. Do not claim an MMO from a local save, mocked player list, or client-only simulation. Do not deploy, migrate production data, purchase services, or use credentials without explicit authority.
