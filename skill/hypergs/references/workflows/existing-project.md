# Existing Project Workflow

## Trigger

Use when a repository already contains game code or assets but lacks HyperGS project memory.

## Procedure

1. Detect the engine and inspect entry points, build instructions, tests, assets, recent changes, and user modifications.
2. Run the safest available build or smoke test before changing code when practical.
3. Infer the lifecycle phase from evidence, not folder names or aspirations.
4. Initialize `.hypergs` without overwriting project files.
5. Record confirmed facts, explicit inferences, risks, and unknowns separately.
6. Recommend one stabilization or advancement objective.

## Completion

Produce an evidence-backed baseline, active studio profile, inferred phase, validation result, and a prioritized next action. Do not rewrite the project merely to match a preferred template.
